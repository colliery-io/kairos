Plan: (1) two-pass schema-sync — provision throwaway `schema_sync_template` tenant, print-schema with search_path pinned to org_schema_sync_template (tenant tables emit unqualified since that is the connection's current_schema), second pass `--schema public` on the same pinned connection (public != default schema so diesel emits `public.x` qualified tables); concatenate deterministically. Open risk: `board_member_capabilities` has no PRIMARY KEY in the S-0004 DDL — diesel print-schema may skip PK-less tables; verifying empirically, resolution to be recorded.
- 2026-07-09: Empirical findings that reshaped the plan (recorded for schema-sync maintainers):
  - search_path pinning via URL `options=` does NOT work for print-schema (diesel lists the `public` schema by default and resolves relations via `regclass`, which then fails). Explicit `--schema` per pass is required.
  - `diesel print-schema --schema public` emits UNQUALIFIED table headers (diesel strips the default schema), and both passes wrap output in a `pub mod {schema} { ... }` block. schema-sync therefore post-processes: unwrap + dedent the module wrapper in both passes; strip the `org_schema_sync_template.` qualification from the tenant pass; ADD `public.` qualification to table headers in the public pass. Output verified deterministic (identical md5 across reruns, including after a full volume wipe).
  - **DDL amendment**: `board_member_capabilities` had `UNIQUE (board_id, user_id, capability)` but no PRIMARY KEY; diesel hard-errors on PK-less tables ("Diesel only supports tables with primary keys"). Added tenant migration `2026-07-09-000001_board_member_capabilities_pk` promoting that UNIQUE constraint to the composite PRIMARY KEY (same three NOT NULL columns — semantically equivalent constraint upgrade, not a redesign). S-0004 should be annotated accordingly (follow-up for the orchestrator).
- 2026-07-09: Implementation landed:
  - `crates/kairos-db/src/schema.rs` — generated, 29 tables (21 tenant unqualified + 8 public `public.*`-qualified); regenerated by the rewritten `angreal db schema-sync` (.angreal/task_db.py) which provisions/drops the throwaway `schema_sync_template` tenant through the real provisioning code.
  - `crates/kairos-db/src/models/{enums,public,teams,boards,templates,items,graph}.rs` — Queryable/Selectable(+Identifiable) row structs and Insertable `New*` structs for all 29 tables; `AsChangeset` `*Changeset` structs for every table with updatable non-key columns. Deliberate omissions: `team_delivery_streams` (pure join table, both columns are the PK — AsChangeset is impossible), `item_history` and `activity_log` (append-only by design). 9 TEXT enums (OrgRole, FieldType, TeamType, BoardLevel, TaskType, Complexity, BucketType, RelationshipType, ActivityAction) via a `text_enum!` macro with FromSql/ToSql, unknown values rejected with a typed `UnknownEnumValue` error; 9 unit tests cover round-trip + rejection per enum. Note: `system_board_defaults.columns` is emitted as `columns_` (`#[sql_name = "columns"]`) by print-schema; models map it back via `#[diesel(column_name = columns_)]`.
  - `crates/kairos-db/src/pool.rs` — `TenantPool` (bb8 + diesel-async `AsyncPgConnection`). Mechanism: `tenant(slug)` validates the slug (same S-0004 pattern as provisioning, so identifier interpolation is safe), checks out an OWNED connection (`get_owned`) and pins `SET search_path TO "org_{slug}", public` BEFORE handing it over; `public_conn()` pins `SET search_path TO public`. Reset-on-return: `TenantConnection::Drop` moves the owned connection into a `tokio::spawn`ed task that runs `SET search_path TO public` and only then releases it to bb8 (the pool can't hand it out mid-reset because bb8 only gets it back when the task drops it); `release()` offers an awaitable deterministic variant. Documented failure mode: no tokio runtime at drop / reset statement failure → connection re-pools with stale path, which is unobservable through the API because every checkout unconditionally re-pins first; the reset is defense-in-depth.
  - Workspace deps added (Cargo.toml): `chrono = "0.4.42"`, `uuid = { version = "1.18.1", features = ["v4"] }`; diesel features extended with `chrono`,`uuid`; kairos-db gains chrono/uuid/tokio.
  - `crates/kairos-db/tests/models_roundtrip.rs` — `models_round_trip` (insert+select through models for organizations/users/organization_members + teams, boards/columns/transitions, strategies (incl.
